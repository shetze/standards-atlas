Classify the clause along four independent semantic dimensions:
1. statement_functions: linguistic or logical force;
2. knowledge_kinds: engineering knowledge represented;
3. applicability_functions: explicit applicability, inclusion, exclusion, exception, or applicability condition;
4. role_semantics: whether role semantics are present and, when explicit, the corresponding role_relations.

A clause may have labels in more than one dimension. Empty lists are allowed when evidence is absent. Use only the supplied clause content; do not infer from document structure.

Classify process-model functions separately from role semantics: objectives, prerequisites, inputs, activities, decisions, branches, sequences, outputs, completion criteria, options, and assumptions. Structural membership in a Scope section is context, not an applicability label. Never return scope_definition.

Applicability is narrow. Set applicability_functions only when the clause explicitly states or changes which subject or normative content applies. Generic conditions, prerequisites, assumptions, structural Scope context, and local process conditions are not applicability unless applicability itself changes. Use inclusion for explicit positive applicability, exclusion for explicit non-applicability, exception for a carved-out case, and applicability_condition only when applicability itself is conditional. Return at most one primary applicability subtype.

Classify techniques, methods, and measures as technique_or_measure. Statement function and knowledge kind are orthogonal. For statement functions, first collect every function directly supported by the complete clause, then choose primary_function as the main communicative purpose. Classify should as recommendation and should not as condemnation unless the wording is merely descriptive. Use warning for explicit risk, limitation, unsafe consequence, unreliable result, invalid assumption, or possible misuse. Preserve supported secondary functions.

Role qualification rules:
- role_semantics_present and role_relations belong to the same role_semantics dimension; they are not independent dimensions.
- Set role_semantics_present=true when the clause explicitly describes a human or organizational role, responsibility, participation, assignment, consultation/information relationship, dependency/independence, membership, or a passive role/action semantics where the actor is omitted.
- An actor must be an explicitly identified human or organizational role, person, group, organization, organizational unit, committee/body, supplier, duty holder, authority, or stakeholder. Being the grammatical subject is not sufficient. Technical objects such as systems, software, hardware, documents, requirements, methods, processes, results, and safety integrity levels are not actors merely because they are grammatical subjects.
- Do not invent a missing actor. Passive role/action semantics such as "A hazard analysis shall be performed" may set role_semantics_present=true while returning role_relations=[].
- Each role relation contains only actor, relation_class, and target. relation_class is open; prefer the core classes performance, responsibility, assignment, dependency, consultation, information, participation, and membership when they fit.
- Target identifies what the actor's relation is about or directed toward. Do not repeat the actor as target unless the text explicitly states a reflexive relation.
- If the text explicitly frames an action as a responsibility or accountability, use responsibility rather than performance. Do not turn applicability, scope, technical properties, logical conditions, or artifact relations into RoleRelations.
- Return every grounded relation separately for clauses containing multiple actors or relations.

Boundary examples:
- "The Assessor shall evaluate the evidence." -> role_semantics_present=true; Assessor / performance / evidence.
- "A hazard analysis shall be performed." -> role_semantics_present=true; role_relations=[].
- "The system shall satisfy the RAMS requirements." -> role_semantics_present=false; role_relations=[].
- "These requirements apply to new systems." -> role_semantics_present=false; role_relations=[]; this is applicability.
- "One responsibility of the technical committee is preparation of its publications." -> technical committee / responsibility / preparation of its publications.

The task applies to clause narrative, not table-derived concepts or relations. Do not project table semantics back onto the containing clause.

Use [] and null when the evidence does not support a label. Confidence values must be JSON numbers from 0.0 through 1.0.
